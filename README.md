# Jev-взвешивание фактов: цена достоверности $0.00004

Калиброванное числовое доверие к каждому факту при ingest в базу знаний — с реальными замерами стоимости, скорости и провалов.

## Что это даёт базе знаний

Автоматическая LLM-вики — это вики, которую пишет не человек, а модель: она читает поток документов, вытягивает факты и складывает по страницам. Идею публично продвигал [Andrej Karpathy](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f): вместо мёртвых корпоративных баз — живой, поддерживаемый LLM слой знаний поверх ваших документов. Через месяц без контроля такая база превращается в свалку: рядом лежат проверенные данные, чужие мнения и вода, а отличить их нельзя — у всех одинаковый ярлык «high». Классический *garbage in, garbage out*, только теперь мусор генерирует уверенным тоном.

Этот метод превращает доверие в **число на каждой странице и каждом факте**, и это меняет поведение базы целиком:

| Было (ярлыки от экстрактора) | Стало (Jev-веса) |
|---|---|
| «high / medium / high» — нельзя сравнивать | `confidence: 0.68` — базу можно **сортировать и фильтровать** по достоверности |
| Мусор накапливается незаметно | Гейт перед записью: волна принимается, только если фактов ≥ N и средний вес ≥ X — **низкодостоверные источники отсекаются до попадания в базу** |
| Экстрактор ставит доверие сам себе | Оценка независима от извлечения, причём **в 2–4 раза дешевле** любого LLM-судьи ($0.00004 против $0.001+ на факт) |
| Ответ ассистента одинаково уверенно звучит для проверенного факта и для слуха | Ассистент может **калибровать тон**: «подтверждено данными» vs «по неподтверждённому сообщению» |
| Массовая чистка базы вручную | Откат весов одной командой (`strip`), пересчёт при смене приоритетов — редактируется формула, не промпты |

Экономика: вся волна из ~3 200 фактов взвешивается за **$0.12 и несколько минут** — то есть стоимостной барьер для «знать, насколько я верю каждому кусочку своей базы», исчезает полностью. Побочный эффект Jev-механики: однажды посчитанные веса живут в данных и продолжают работать — при поиске, при ранжировании ответов, при решении «что выбросить при сжатии контекста» — уже бесплатно.

Подробности — ниже.

> **TL;DR.** Когда Jev (первая «System One модель» TypeSafe) вышел 15.09.2026, все обсуждали роутинг и классификацию тикетов. Мы применили его к другой задаче — **калибровке доверия к фактам** при пополнении базы знаний из потока документов. Один параллельный проход Jev на факт стоит **~$0.00004** и даёт четыре оси оценки (достоверность, значимость, конкретность, тип). 3 200 фактов ≈ **$0.12** и несколько минут. Массовый бэкфилл мы не стали делать — и это самое полезное открытие.

## 1. Проблема: `confidence: high` — это не число

LLM-вики и базы знаний, собираемые автоматически, быстро накапливают мусор. Стандартная практика — ярлыки `low / medium / high`, проставляемые моделью-экстрактором. Три проблемы:

1. **Ярлык не агрегируется.** Нельзя усреднить «high» и «medium», нельзя отсортировать базу по достоверности, нельзя задать порог гейта («волна принимается, если фактов ≥ N и средний confidence ≥ X»).
2. **Экстрактор оценивает сам себя.** Тот же prompt, который выдёргивает факты, ставит им «достоверность» — корреляция с качеством извлечения близка к единице, а с реальностью — неизвестна.
3. **Дублирование оплаты.** Классический fallback — прогнать каждый факт через дешёвую LLM «оцени 0–10» — это генерация токенов: парсинг, валидация, цена выходных токенов, нестабильный JSON.

> [!IMPORTANT]
> Ключевая мысль: достоверность факта — это **решение**, а не текст. Решения должны возвращаться типизированными, с вероятностью, за долю цента — ровно тот класс задач, под который TypeSafe построил Jev.

## 2. Идея: решение вместо генерации

Jev не генерирует текст. Категория, которую TypeSafe назвал **System One**, отсылает к Даниэлю Канеману («Думай медленно… решай быстро»): System 2 — медленное рассуждение в цепочке мыслей (это сегодняшние LLM), System 1 — быстрое интуитивное суждение. Само имя **Jev** — от [парадокса Джевонса](https://en.wikipedia.org/wiki/Jevons_paradox) (Уильям Стэнли Джевонс, 1865): когда ресурс радикально дешевеет, его потребление не падает, а взрывается. Тезис TypeSafe — то же с «решениями»: удешевление машинного суждения в сотни раз не сократит AI-spend, а умножит количество решаемых задач.

Технически: Jev принимает `state` (сущность + источник + текст утверждения) и набор типизированных вопросов; возвращает `noul` (вероятность 0–1), `score` (позиция на порядковой шкале) и `choice` (выбор из заданных опций) — всё за **один параллельный проход** по всем вопросам сразу. Выходных токенов нет, поэтому выход бесплатен; платите только за вход ($0.042 / 1M токенов).

Сдвиг парадигмы: вес факта становится **первоклассным числом в данных** (frontmatter страницы), а не меткой, которую надо интерпретировать. `confidence: 0.68` можно усреднять, сортировать, гейтить и откатывать. По сути это замена паттерна **LLM-as-a-judge** («попроси модель оценить и распарси ответ») на нативное калиброванное решение — там, где оценка нужна без генерации текста.

## 3. Архитектура

```text
поток документов ──► экстракция фактов (LLM, существующий пайплайн)
                              │
                              ▼
                 дедуп по (claim, entity)          ◄── волны читают один источник
                              │                        по 2–3 раза — не платить дважды
                              ▼
        ┌────────── Jev, 8 воркеров, 1 проход на факт ──────────┐
        │  reliability (noul)   importance (score 0–3)          │
        │  specificity (score)  kind (choice: 4 опции)          │
        └──────────────────────────┬────────────────────────────┘
                                   ▼
                     вес = 0.50·rel + 0.25·kind + 0.15·imp + 0.10·spec
                                   ▼
              агрегат по странице → confidence / importance / facts / cost
              в frontmatter (пишется хирургически, построчно)
```

Инвариант: **пер-факт веса живут в кеш-файле (дайджесте), не в теле страницы** — порядок фактов задаётся кодом, а последующая кристаллизация/сжатие страницы не дорожает.

## 4. Рубрика: четыре вопроса за один проход

Одна Jev-пасса на факт, четыре вопроса одновременно (все в одном запросе, поэтому дёшево):

| Ось | Тип | Вопрос | Шкала |
|---|---|---|---|
| `reliability` | noul | «Утверждение подтверждается конкретными данными источника, без домыслов, мнений и оговорок?» | вероятность 0–1 |
| `importance` | score | «Значимость для базы знаний» | Фон / Второстепенное / Важное / Ключевое |
| `specificity` | score | «Насколько конкретны данные?» | Общее / Частичное / Конкретное / Точное |
| `kind` | choice | «Чем является фрагмент?» | факт / процедура / обсуждение / шум |

Финальный вес:

```python
kind_factor = {"факт": 1.0, "процедура": 0.75, "обсуждение": 0.5, "шум": 0.15}
weight = 0.50 * reliability + 0.25 * kind_factor[kind] \
       + 0.15 * (importance / 3) + 0.10 * (specificity / 3)
```

> [!NOTE]
> Почему такие коэффициенты. Достоверность — главная ось (0.50): недостоверный «ключевой» факт опаснее достоверного «фонового». Тип фрагмента — второй по силе предиктор (0.25): «шум» с высоким noul всё равно мусор. Значимость и конкретность — тонкая регулировка (0.15/0.10). Коэффициенты — не святое: при смене приоритетов базы редактируется формула, а не промпты.

Ярлык для обратной совместимости: ≥0.75 → `high`, 0.5–0.75 → `medium`, <0.5 → `low`.

## 5. Что зафиксировать до внедрения

1. **Пин версии модели** (`typesafe/jev-1.13`), а не алиас `~latest` — при тюнинге порогов движущаяся версия сделает замеры невоспроизводимыми.
2. **Дедуп до вызова модели**, по нормализованной паре (текст утверждения, сущность). Плоские и вложенные списки фактов в дайджесте дублируют друг друга — платим один раз.
3. **Ретраи только на 429/5xx** с экспоненциальной паузой; любая другая ошибка — запись в результат с `error`, а не остановка волны.
4. **Frontmatter править построчно-хирургически.** Полный YAML-раунд-трип ломает вложенные списки с временными метками и отступами. Удаляем только весовые строки, вставляем новые после первой строки блока.
5. **Матчинг сущность → страница**: токенизация с синонимами и вырезанием служебных слов, покрытие токенов сущности ≥ 0.7, штраф за лишние токены имени файла. Без этого половина фактов не найдёт страницу.
6. **Математика — в коде, не в вопросах.** Jev честно плох в счёте и сравнении дат (это задокументировано и самим TypeSafe) — рубрика не должна требовать арифметики.

## 6. Замеры

Все числа — реальный прогон на собственной базе знаний (потоковые источники: оперативные сводки, транскрипты встреч, мессенджер, почта, табличные графики).

### Достоверность по типу источника (средний `reliability`)

| Тип источника | reliability |
|---|---|
| Транскрипты встреч | 0.60–0.65 |
| Табличные графики | 0.60–0.65 |
| Мессенджер / почта | ~0.55 |
| Оперативные сводки | **0.48** |

> [!WARNING]
> Самый «официальный» источник оказался самым низкодостоверным: сводки пишутся людьми с обобщениями и оговорками, а транскрипты — дословная речь. Интуиция «официальное = достоверное» тут переворачивается — и только числовая метрика это показала.

### Две оси действительно независимы

Корреляция reliability ↔ importance по всем фактам: **r ≈ 0.15**. Ключевые факты бывают сомнительными, а фоновые — железобетонными. Именно поэтому надёжность и значимость нельзя схлопывать в один «quality score» — нужны отдельные оси с отдельными весами.

### Главный провал: страницы с 1–2 фактами

**53% страниц** базы содержат 1–2 факта. Средний вес одного-двух фактов — это экстремум на n=1: страница из одного «шумного» факта получает confidence 0.2, страница из одного удачного — 0.9. Вывод, который мы приняли:

- ❌ **Массовый бэкфилл старых страниц не делать** — веса станут шумом, который хуже честного «no data».
- ✅ Веса ложатся **постепенно, только на новые ingest-волны**, где фактов на страницу достаточно.

## 8. Минимальный код

Запускаемый пример: [`examples/weight_facts.py`](examples/weight_facts.py). Зависимостей нет — только stdlib. На macOS системный питон без дефолтного CA-bundle: пример сам подхватывает `/etc/ssl/cert.pem` (иначе `CERTIFICATE_VERIFY_FAILED`).

```bash
export OPENROUTER_API_KEY=sk-or-...
python examples/weight_facts.py "Модуль экспорта в CSV падает с 500 для всех воркспейсов с утра."
```

Ключевые строки (полная версия в примере):

```python
RUBRIC = {
    "reliability": {"type": "noul",
        "instructions": "Утверждение подтверждается данными источника, без домыслов?"},
    "importance": {"type": "score",
        "instructions": "Значимость для базы знаний.",
        "criteria": ["Фон", "Второстепенное", "Важное", "Ключевое"]},
    "kind": {"type": "choice", "instructions": "Чем является фрагмент?",
        "criteria": {"факт": "состояние/событие с опорой на данные",
                     "процедура": "поручение, план",
                     "обсуждение": "мнение, спор",
                     "шум": "вода, повтор"}},
}
resp = json.load(urlopen(Request(URL, data=json.dumps(
    {"model": "typesafe/jev-1.13", "state": state, "questions": RUBRIC}).encode(),
    headers={"Authorization": f"Bearer {KEY}", "Content-Type": "application/json"})))
weight = 0.50 * resp["answers"]["reliability"]["noul"] \
       + 0.25 * KIND_F[resp["answers"]["kind"]["choice"]] \
       + 0.15 * resp["answers"]["importance"]["score"] / 3
```

## 9. Ограничения

- **n=1 — не метрика.** Метод требует достаточного числа фактов на страницу; при 1–2 фактах агрегат шумит. Это главный и самый дорогой урок.
- **Уверенный неверный ответ.** Схема гарантирует валидный тип, но не валидную семантику: noul 0.9 может означать «уверенная ошибка». Пороги гейта подбираются по своей выборке.
- **Качество на входе.** Jev оценивает то, что дал экстрактор. Мусорный факт получит низкий вес — но если экстрактор потерял факт целиком, взвешивать нечего.
- **Условия использования хостед-модели ограничивают прямое бенчмаркирование** — поэтому здесь замеры своего пайплайна, а не сравнительные таблицы с LLM.
- Русскоязычная рубрика работала без нареканий, но при переносе на другой язык формулировки criteria стоит перепроверить: смысл вопроса должен жить в описаниях, а не в id вопросов.

## 10. Итог

1. Достоверность факта — типизированное решение; Jev возвращает его с вероятностью за ~$0.00004 и ~70 мс.
2. Числовое `confidence` в данных заменяет ярлыки: агрегация, гейты, сортировка, откат.
3. Самая ценная находка — негативная: **не вешать веса на страницы, где мало фактов**. Метрика без понимания своей плотности данных врёт красивее любого ярлыка.

## Об авторе

**Roman Shemley** — это моя первая публикация. За ней стоит год экспериментов над идеей, которую Karpathy описал как «LLM Wiki», а пользователи давно окрестили **вторым мозгом**: вики, которую не пишут руками, а выращивают — LLM сам читает поток документов, компилирует страницы, поддерживает перекрёстные ссылки и оценивает достоверность каждого факта. Как любой живой орган, второй мозг нуждается в иммунной системе: без неё он незаметно заполняется уверенностью в собственном мусоре. Эта статья — про такую иммунную систему: Jev стал первым инструментом, который сделал проверку достоверности одновременно дешёвой и численной. Всё изложенное — из реальных прогонов на собственной базе знаний, которая сегодня работает вторым мозгом её автора.

**Продолжение следует.** В следующих частях: открытый код весовщика и аннотатора, калибровка порогов гейта по своей выборке, и что происходит, когда попытаться обучить собственную Jev-подобную модель на своих рубриках.
